## 1. Neuroscience & Cognitive Architecture (Biological Grounding)

The human brain is the most energy-efficient, resilient, and adaptive computing system in known existence. AI-Builder-Brain borrows key neural mechanisms to govern autonomous AI systems:

1. **Dual-Process Cognitive Engine (System 1 vs System 2)**:
   - **System 1 (Intuitive Fast-Path)**: Rapid pattern matching, syntax generation, and low-latency scaffolding.
   - **System 2 (Deliberate Analytical Verification)**: Deep forensic reasoning, race-condition checking, boundary-case proofs, and compiler validation before execution.
2. **Complementary Learning Systems (CLS Theory - Hippocampus & Neocortex)**:
   - **Fast Episodic Ingestion (Hippocampus)**: Captured in `.project-brain/incidents/` and temporary harvest staging (`07_PROJECT_LEARNING/`).
   - **Slow Semantic Consolidation (Neocortex)**: Distilling raw experiences into permanent universal engineering patterns (`05_KNOWLEDGE/engineering-patterns.md`) without catastrophic forgetting.
3. **Attention & Working Memory Constraints (Miller's $7 \pm 2$ Law)**:
   - Context windows must never be polluted with raw bloat. Attention is directed strictly to high-signal invariants (< 300 tokens) using the Surgical Router.

## 2. Psychology & The Observable Mind (Human-System Resonance)

Code does not execute in a vacuum; it interacts with the human psyche. Software that ignores psychology creates cognitive friction and user rejection.

1. **The Observable Mind & Metacognition**:
   - The AI must maintain self-awareness of its internal reasoning state: *"Am I assuming or do I know with empirical evidence?"*
   - Real-time observability: Tracking confidence vs certainty, surfacing hidden edge-cases, and explaining decisions transparently.
2. **Cognitive Load Minimization (Sweller's Theory)**:
   - **Intrinsic Load**: The essential complexity of the problem.
   - **Extraneous Load**: Bad UI, confusing APIs, unnecessary nesting—strictly eliminated.
   - **Germane Load**: Mental effort devoted to actual problem-solving—maximized.
3. **Mental Model Synchronization**:
   - The conceptual model in the developer's mind and the runtime model in the software must align with zero surprise. UI, CLI, and APIs must follow principle of least astonishment.

## 3. Philosophy & First-Principles Reasoning (Epistemological Truth)

Philosophy is not abstract speculation; it is the discipline of defining truth, sound reasoning, and purpose.

1. **Epistemology (How Do We Know What Is True?)**:
   - Never accept code as correct because *"it looks plausible"* or *"an AI generated it"*. Truth in engineering requires empirical verification (compilation, runtime execution, boundary tests).
2. **Socratic Falsification & Dialectics**:
   - For every architectural decision, formulate the strongest counter-argument: *"Under what conditions will this design fail catastrophically?"* (e.g. Network partition, disk full, out-of-memory, concurrent write lock).
3. **Teleology (Purpose-Driven Construction)**:
   - Every module, function, and database table must have an unambiguous *raison d'être* (reason for existence). If a piece of code does not serve a verified purpose, delete it.
4. **First-Principles Decomposition (Aristotle & Descartes)**:
   - Strip problems down to their fundamental, undeniable truths (physical constraints, byte sizes, clock cycles, network latencies) and build upward from there.

## 4. Science & The Empirical Method (Rigorous Verification)

Software engineering is applied computational science. It must obey scientific standards of proof.

1. **Popperian Falsification**:
   - A system cannot be proven correct by running 1,000 happy-path tests. It is validated by actively trying to break it with edge cases, fuzzing, and fault injection.
2. **Entropy Reduction (The Second Law of Software Dynamics)**:
   - Unmanaged software naturally accumulates technical debt, state drift, and architectural decay (entropy). AI-Builder-Brain continuously acts as an anti-entropy shield through refactoring, dead-code removal, and regression gates.
3. **Causal Inference vs Spurious Correlation**:
   - In debugging, never treat symptoms as root causes. Trace the causal DAG (Directed Acyclic Graph) of state mutations from trigger to failure.
