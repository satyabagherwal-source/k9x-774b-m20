# Brain Evolution Protocol

The Master AI-Builder-Brain evolves through controlled promotion, not automatic dumping.

## Complete evolution cycle

Project work
→ observation
→ project learning
→ candidate reusable knowledge
→ verification
→ review/promotion decision
→ Master Brain update
→ versioned change
→ future use
→ new evidence
→ reevaluation.

## Promotion decision

A candidate may be promoted when:

- the observation is understood,
- evidence supports the stated claim,
- its scope is explicit,
- it is useful beyond one isolated project,
- and there is no known stronger conflicting evidence.

If these conditions are not met, keep the candidate in project learning or verification.

## Updating existing knowledge

When new evidence strengthens an existing rule, improve the existing knowledge while preserving its provenance.

When new evidence limits a rule, add the limitation.

When new evidence contradicts a rule, do not silently overwrite the history. Record the change and its reason.

## Versioning

Meaningful Brain changes should be tracked in version control.

Git provides commit history and can create a new commit that reverts an earlier change, allowing the evolution history to remain inspectable.

The Brain's version number should describe the state of the Master Brain, not the version of an individual project.

## Human oversight

AI may:
- identify candidate learning,
- prepare evidence,
- propose classification,
- draft a Brain change,
- and explain why it should be promoted.

AI must not treat its own generated statement as sufficient evidence.

For consequential or uncertain promotion decisions, human review is required.

## Goal

The goal is not maximum growth.

The goal is a smaller body of increasingly reliable, reusable knowledge.
