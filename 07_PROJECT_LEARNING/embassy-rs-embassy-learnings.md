## 1. Executive Forensic Architecture & System Mechanics

### Core Mission & Domain Boundaries
`embassy` solves zero-allocation, deterministic asynchronous execution on bare-metal embedded targets (`no_std`). Traditional RTOS kernels (FreeRTOS, Zephyr) allocate discrete runtime stacks per thread/task, leading to severe memory over-provisioning (RAM exhaustion) and high context-switching overheads (register spill/fill cycles across SysTick ISRs). Embassy eliminates per-task stacks entirely by lowering Rust `async/await` state machines into statically sized, cooperatively scheduled compiler-generated generators residing in static memory (`.bss`/`.data`), driving wakeups via hardware peripheral interrupts.

```
                      +---------------------------------------+
                      |         Embedded Application          |
                      +---------------------------------------+
                                          |
                +-------------------------+-------------------------+
                v                                                   v
     +---------------------+                               +------------------+
     |   embassy-time      |                               |   embassy-net    |
     | Global Timers / RTC |                               | Zero-copy TCP/IP |
     +---------------------+                               +------------------+
                |                                                   |
                +-------------------------+-------------------------+
                                          v
                      +---------------------------------------+
                      |           embassy-executor            |
                      |  Intrusive RunQueue (Cordyceps)       |
                      |  TaskHeader State Machine (Atomic/CS) |
                      +---------------------------------------+
                                          |
                +-------------------------+-------------------------+
                v                                                   v
     +---------------------+                               +------------------+
     | Hardware Abstraction|                               |   Hardware Co-   |
     | Layers (HALs):      |                               |   Processors &   |
     | STM32, NRF, RP, etc.|                               |   Engines (PKA)  |
     +---------------------+                               +------------------+
                |                                                   |
                +-------------------------+-------------------------+
                                          v
                      +---------------------------------------+

                      +---------------------------------------+
```

### Critical Subsystem Abstractions
1. **Intrusive Task Allocation & Static Lifetimes (`embassy-executor`)**:
   - `TaskHeader`: Intrusively holds scheduling metadata (`run_queue_item: cordyceps::sorted_list::Links<TaskHeader>`), poll function pointers (`poll_fn`), executor identification, and an atomic/critical-section synchronization word (`State`).
   - Tasks are bound to static storage declarations generated by `#[embassy_executor::task]`, completely bypassing runtime heap allocation.
2. **Atomic / Critical-Section Polyfilled RunQueues (`run_queue.rs`)**:
   - Architectures with atomic pointer CAS (`target_has_atomic = "ptr"`) utilize `cordyceps::TransferStack<TaskHeader>`. The enqueue operation is lock-free: `task.next = head; CAS(&head, old, task)`.
   - Targets lacking hardware atomic pointers (e.g., ARM Cortex-M0+, AVR) substitute `MutexTransferStack<TaskHeader>`, backed by `critical_section::Mutex<core::cell::UnsafeCell<cordyceps::Stack<TaskHeader>>>`.
3. **Hardware-Triggered Wakers & Interrupt Demuxing**:
   - Wakers do not interact with OS schedulers. A hardware interrupt service routine (ISR) fires upon DMA completion or peripheral ready flags, updates the peripheral driver state, and invokes `waker.wake()`.
   - `wake()` marks the task's atomic state as `STATE_RUN_QUEUED` via `fetch_or` and pushes the intrusive node to the executor's `TransferStack`. It then issues an event to the CPU core (e.g., `sev` on ARM Cortex-M or unmasking software interrupt).
4. **DMA & Physical Memory Invariants (`embassy-nrf`, `embassy-stm32`)**:
   - Peripherals utilizing Direct Memory Access (e.g., Nordic EasyDMA) operate on physical bus master addresses. Pointers pointing to non-SRAM memory spaces (e.g., internal Flash, Memory-Mapped IO registers) cause bus faults or silent corruptions. Embassy enforces hardware bounds checks (`slice_in_ram`) and provisions static/stack bounce buffering (`bounce_chunks`).

## 2. Net-New Universal Engineering Rules (Candidates for Master Brain)

### 1. Verification of Hardware Bus Master Address Spaces for DMA Buffers
**RULE**:
Before arming any bus master hardware DMA engine with a pointer, the runtime driver MUST validate that the physical memory range of the target buffer resides completely inside the accessible RAM address space (`slice_in_ram`). If any segment falls outside RAM (e.g., Flash `.rodata`), the driver MUST route the transfer through a RAM-backed bounce buffer.

**WHY**:
Hardware DMA engines (such as Nordic Semiconductor EasyDMA or STM32 DMA controllers) route memory transfers through internal crossbar buses directly to SRAM. Memory-mapped flash memory controllers cannot service bus-mastered read/write requests from peripheral DMA engines in the same manner as the CPU core. Supplying a pointer to `.rodata` (Flash) to an EasyDMA pointer register results in an immediate `HardFault`, a silent transfer abort, or bus parity errors that compromise firmware reliability.

**WHEN TO APPLY**:
Apply in all bare-metal drivers, HAL implementations, or kernel drivers where hardware DMA engines directly read or write user-provided slices across non-unified bus matrices.

**VERIFIED IMPLEMENTATION PATTERN**:
```rust
const SRAM_LOWER: usize = 0x2000_0000;
const SRAM_UPPER: usize = 0x3000_0000;
const BOUNCE_LEN: usize = 256;

#[inline(always)]
pub fn slice_in_ram<T>(slice: *const [T]) -> bool {
    if slice.is_empty() {
        return true;
    }
    let ptr = slice as *const T as usize;
    let size = slice.len().checked_mul(core::mem::size_of::<T>())
        .expect("Buffer length overflow");
    
    ptr >= SRAM_LOWER && (ptr.checked_add(size).map_or(false, |end| end <= SRAM_UPPER))
}

pub fn transfer_dma_safe(data: &[u8], max_chunk: usize, mut dma_send: impl FnMut(&[u8])) {
    if slice_in_ram(data) {
        for chunk in data.chunks(max_chunk) {
            dma_send(chunk);
        }
    } else {
        let mut bounce = [0u8; BOUNCE_LEN];
        let chunk_size = max_chunk.min(BOUNCE_LEN);
        for chunk in data.chunks(chunk_size) {
            bounce[..chunk.len()].copy_from_slice(chunk);
            dma_send(&bounce[..chunk.len()]);
        }
    }
}
```

**NEGATIVE CONSTRAINT**:
```rust

    // BUG: If data is a string literal or const table in Flash (e.g., 0x0000_1000 on nRF),
```

### 2. Immediate Reactor Wakeup Registration Invariant
**RULE**:
When registering an asynchronous waker with an underlying event source, if the underlying resource's poll operation reports that readiness conditions are already met (`Poll::Ready`), the driver MUST invoke `waker.wake_by_ref()` immediately prior to exiting the registration block.

**WHY**:
Level-triggered and edge-triggered file descriptor pollers (or ring-buffer poll loops) only generate notifications when transitioning between states. If an asynchronous driver queries the readiness of an external queue or descriptor during waker registration and that resource is already readable/writable, no future edge event will be emitted. Failing to wake the runner causes the task to sleep indefinitely, hanging the state machine.

**WHEN TO APPLY**:
Apply in all async runtime adapters, network drivers (e.g., TUN/TAP, socket wrappers), and IPC bridges that decouple readiness detection from the executor poll cycle.

**VERIFIED IMPLEMENTATION PATTERN**:
```rust
use core::task::{Context, Poll, Waker};

pub trait DriverResource {
    fn poll_readable(&mut self, cx: &mut Context<'_>) -> Poll<()>;
}

pub struct TunTapDriver<R: DriverResource> {
    device: R,
}

impl<R: DriverResource> TunTapDriver<R> {
    pub fn register_waker(&mut self, waker: &Waker) -> Result<(), ()> {
        let mut cx = Context::from_waker(waker);
        // INVARIANT: If already readable, immediately wake the waker to prevent lost event deadlock
        if self.device.poll_readable(&mut cx).is_ready() {
            waker.wake_by_ref();
        }
        Ok(())
    }
}
```

**NEGATIVE CONSTRAINT**:

### 3. Coprocessor Redundancy and Security Initialization Invariant
**RULE**:
Low-level initialization routines (`__pre_init`) on microcontrollers featuring redundancy coprocessors (RCP) or security sub-engines MUST interrogate the coprocessor hardware status registers before issuing configuration writes. If the coprocessor's state is invalid (e.g., missing salt or uninitialized canary), the firmware MUST initialize it and signal core synchronization primitives before resuming normal instruction execution. Writing to an already valid salt register MUST be actively guarded against to prevent security coprocessor hardware faults.

**WHY**:
Modern multi-core secure microcontrollers (such as RP2350 with Arm Cortex-M33 and RCP) execute coprocessor instructions that fault immediately if the RCP coprocessor is unmapped in the Coprocessor Access Control Register (`CPACR`) or if its operational salt has not been initialized. When a hardware debugger (e.g., `probe-rs`, OpenOCD) resets and halts execution or jumps directly to RAM, the BootROM initialization logic is bypassed. Secondary cores (`PROC1`) stalled in BootROM awaiting salt synchronization will deadlock or crash when woken unless primary core initialization sets the salts and signals an event (`sev`). Re-writing an already valid salt also triggers a hardware fault.

**WHEN TO APPLY**:
Hardware startup code, crt0 replacement hooks, and BootROM bypass vectors on security-hardened or dual-core platforms (RP2350, Cortex-M33, TrustZone systems).

**VERIFIED IMPLEMENTATION PATTERN**:

## 4. Microscopic Code-Level Invariants

### 1. Micro-Syntax & Token-Level Precision
- **Atomic Bitwise Flag Decomposition**: In `state_atomics.rs` vs `state_atomics_arm.rs`, atomic flags are packed into `u32` or individual `AtomicBool` byte slots depending on core memory architecture.
  ```rust
  // CRITICAL INVARIANT: Bit shifts MUST match memory alignment across targets
  pub(crate) const STATE_SPAWNED: u32 = 1 << 0;
  pub(crate) const STATE_RUN_QUEUED: u32 = 1 << 8; // Bit 8 maps to byte 1 in memory
  ```
  On ARM, byte-level operations (`AtomicBool::swap`) are utilized because Cortex-M instructions (`ldrex`/`strex`, or standard byte stores on ARMv7+) can manipulate individual bytes without loading and masking the full 32-bit register. If an atomic mask operation inadvertently overlaps, task despawn will corrupt the `run_queued` state.
- **Bitwise Power-of-Two Alignment Arithmetic**:
  ```rust
  pub(crate) fn round_down(x: u32, a: u32) -> u32 {
      debug_assert!(a.is_power_of_two());
      x & !(a - 1)
  }
  pub(crate) fn round_up(x: u32, a: u32) -> u32 {
      debug_assert!(a.is_power_of_two());
      (x + (a - 1)) & !(a - 1)
  }
  ```
  *Hazard*: In `round_up`, if `x + (a - 1)` wraps around `u32::MAX`, integer overflow traps are triggered in debug mode. In production `no_std` release profiles with overflow checks disabled, it rounds down to zero, causing buffer truncation.

### 2. Infinite Loop & Recursion Guards
- **Executor Busy-Wait Livelock Prevention**: In `run_queue.rs`, when the standard runqueue executes `dequeue_all`:
  ```rust
  let taken = self.stack.take_all();
  for taskref in taken {
      run_dequeue(&taskref);
      on_task(taskref);
  }
  ```
  *Loop Termination Proof*: `self.stack.take_all()` detaches the entire current stack of tasks atomically, replacing the head pointer with null. If a task invokes `wake()` on itself while inside `on_task`, it is enqueued into the newly emptied `TransferStack`, NOT the current `taken` iterator. The current batch finishes deterministically, completely preventing single-task event-loop starvation of other tasks.
- **Timeout Loops over Asynchronous Predicates (`cyw43/src/util.rs`)**:
  ```rust
  pub(crate) async fn try_until(mut func: impl AsyncFnMut() -> bool, duration: Duration) -> Result<(), Error> {
      let tick = Duration::from_millis(1);
      let mut ticker = Ticker::every(tick);
      let ticks = duration.as_ticks() / tick.as_ticks();
      for _ in 0..ticks {
          if func().await {
              return Ok(());
          }
          ticker.next().await;
      }
      Err(Error)
  }
  ```
  *Guard*: Uses a bounded loop (`0..ticks`) rather than evaluating `Instant::now() >= end_time`. If the hardware clock jumps or wraps, or if `func().await` takes longer than expected, the loop is guaranteed to terminate within a bounded number of iterations.

- **Zero-Copy Command Header Prepending (`cyw43/src/util.rs`)**:
  Network and display drivers must prepend physical bus headers (e.g., SPI 4-byte command words) without copying payloads:
  ```rust
  pub struct WriteBuffer {
      buf: Aligned<A4, [u8]>,
  }
  impl WriteBuffer {
      pub fn cmd(&mut self) -> &mut [u8] { &mut self.buf[..4] }
      pub fn buf(&mut self) -> &mut [u8] { &mut self.buf[4..] }
  }
  impl ops::Index<ops::RangeTo<usize>> for WriteBuffer {
      type Output = Self;
      fn index(&self, mut range: ops::RangeTo<usize>) -> &Self::Output {
          range.end += 4; // Shift indexing past the physical transport header
          unsafe { &*(&self.buf[range] as *const Aligned<A4, [u8]> as *const [u8] as *const WriteBuffer) }
      }
  }
  ```
  *Safety Contract*: Strict 4-byte alignment (`Aligned<A4, [u8]>`) is enforced. Supplying an unaligned buffer to high-speed DMA or SPI results in unaligned memory access exceptions on Cortex-M0/M3.

### 4. Backend Concurrency & Memory Safety
- **RP2350 Idle `WFE` Event Retention Hazard**:
  In `embassy-executor/src/raw/run_queue.rs`:
  ```rust
  #[inline]
  fn definitely_empty(&self) -> bool {
      #[cfg(target_has_atomic = "ptr")]
      { self.stack.is_empty() }
      #[cfg(not(target_has_atomic = "ptr"))]
      { false }
  }
  ```
  *Forensic Hazard*: On RP2350, any exclusive memory access (e.g., `LDREX`/`STREX` or atomic swap) implicitly sets the internal ARM core Event Register. If `take_all()` is executed blindly on an empty queue, the event register remains set, causing the subsequent idle loop instruction `asm!("wfe")` to wake immediately instead of putting the CPU to sleep. Checking `definitely_empty()` before issuing an atomic exchange preserves the low-power sleep state.
- **Critical-Section Re-entrancy Protection**:
  In `MutexTransferStack`:
  ```rust
  let inner = unsafe { &mut *self.inner.borrow(token).get() };
  ```
  A `CriticalSection` prevents concurrent execution across interrupt boundaries, but does NOT prevent local re-entrancy. The implementation guarantees that `self.inner` is never exposed or recursively accessed within the critical section token scope.
