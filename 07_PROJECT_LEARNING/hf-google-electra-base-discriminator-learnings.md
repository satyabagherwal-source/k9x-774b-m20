# Project Learning Record (Full-Spectrum Forensic Harvest): google/electra-base-discriminator

## 1. Executive Forensic Architecture & System Mechanics

**Technical Problem Solved:**
The `google/electra-base-discriminator` repository addresses the computational inefficiency of standard BERT pre-training (Masked Language Modeling). Standard BERT masks only 15% of tokens, meaning the model only learns from a small fraction of the input data. ELECTRA (Efficient Conditioned Pre-training for Language Understanding) replaces this with a **Discriminator** architecture. Instead of predicting masked tokens, the model classifies *every* token in the sequence as either "Real" (from the original corpus) or "Fake" (generated by a separate Generator network). This allows the model to learn from 100% of the input tokens, significantly reducing the compute required to reach state-of-the-art performance.

**Architectural Boundaries & Subsystems:**
1.  **The Discriminator (This Repo):** A Transformer encoder (12 layers, 768 hidden size, 12 heads) that takes a sequence of token IDs and outputs a binary classification logit for *each* position. It does not generate text; it judges authenticity.
2.  **The Generator (Implicit/External):** A small GPT-2 style model that generates "fake" tokens to train the discriminator. This repo contains *only* the discriminator weights.
3.  **Tokenization Boundary:** Uses `ElectraTokenizerFast` (Rust-based HuggingFace tokenizer). Critical invariant: The tokenizer must handle `do_lower_case: true` and `model_max_length: 512`.
4.  **Inference Interface:** The model outputs raw logits. The user is responsible for applying the sigmoid/rounding logic to convert logits to binary predictions (0 or 1).

**Critical Subsystem Abstractions:**
*   **`ElectraForPreTraining`**: The core class. It wraps the `ElectraModel` encoder and adds a `Linear` head (`discriminator`) that maps hidden states to 2 classes (Real/Fake).
*   **State Ownership**: The model owns the weight matrices for embeddings, attention, feed-forward networks, and the final discriminator head. It does *not* own the generator weights.
*   **Data Flow**: Input Token IDs $\rightarrow$ Embedding + Position Embedding $\rightarrow$ 12 Transformer Blocks $\rightarrow$ Hidden States $\rightarrow$ Linear Discriminator Head $\rightarrow$ Logits (Real vs Fake).

### 1. Discriminator Output Normalization Invariant
**RULE**:
When using a pre-trained ELECTRA discriminator for inference, you MUST apply `torch.round((torch.sign(logits) + 1) / 2)` or equivalent binary thresholding to convert raw logits into discrete token authenticity labels (0=Fake, 1=Real). You MUST NOT interpret raw logits as probabilities directly without sigmoid, nor assume the output is already binary.
**WHY**:
The `ElectraForPreTraining` model outputs raw logits from a linear layer, not probabilities. The training loss uses `CrossEntropyLoss` on these logits. If an agent treats the raw float output as a boolean or probability without normalization, it will produce nonsensical results (e.g., a logit of -0.5 might be interpreted as "somewhat real" rather than "fake"). The specific formula `(sign(x) + 1) / 2` maps negative logits to 0 and positive to 1, which is the standard convention for this specific HuggingFace implementation's output interpretation in the README.
**WHEN TO APPLY**:
Any inference pipeline using `ElectraForPreTraining` or similar discriminator-based NLP models where the output is a per-token classification.
