## 1. Executive Forensic Architecture & System Mechanics

`emberstack/kubernetes-reflector` is a specialized Kubernetes operator written in C# (.NET) designed to solve cross-namespace synchronization and distribution of configuration data (`V1Secret` and `V1ConfigMap`). In multi-tenant and microservice architectures, secrets (such as TLS wildcards generated by `cert-manager`) and ConfigMaps (such as shared enterprise PKI bundles) natively reside in a single provisioning namespace (e.g., `cert-manager` or `kube-system`). Kubernetes strictly prevents cross-namespace volume mounting or secret references as a hard isolation boundary.

```

+--------------------------------------------------------------------------------------------------+

          | Watch (HTTP/1.1 Chunked Stream)  | Watch (HTTP/1.1 Chunked Stream)       | List/Patch
          |                                  v                                       v
+-----------------------+          +-----------------------+               +-----------------------+
|  SecretWatcher :      |          |  ConfigMapWatcher :   |               |  NamespaceWatcher :   |
|  WatcherBackgroundSvc |          |  WatcherBackgroundSvc |               |  WatcherBackgroundSvc |
+-----------------------+          +-----------------------+               +-----------------------+
          |                                  |                                       |
```

### Architectural Subsystem Decomposition

1. **Watch Engine (`WatcherBackgroundService<TResource>`)**:
   - Manages the lifecycle of long-lived HTTP chunked transfer-encoding streams against `/api/v1/watch/secrets`, `/api/v1/watch/configmaps`, and `/api/v1/watch/namespaces`.
   - Utilizes `Polly.Core` pipelines to wrap watcher instantiation, handling HTTP timeouts, transport disconnects, and transient network socket closures without terminating the host runtime (`IHostedService`).
   - Uses an explicit `IWatcherClosedHandler` / `IWatcherEventHandler<T>` contract decoupled via reactive or channel-based decoupled consumers.

2. **Annotation Parser & Contract Engine (`MirroringProperties`, `Annotations`)**:
   - Evaluates metadata directives declared on resources:
     - `reflector.v1.k8s.emberstack.com/reflection-allowed`: Boolean string enforcing push permissions.
     - `reflector.v1.k8s.emberstack.com/reflection-allowed-namespaces`: Comma-separated namespace names or glob patterns (evaluated by `GlobMatcher`).
     - `reflector.v1.k8s.emberstack.com/reflection-auto-enabled`: Automatic namespace discovery flag.
     - `reflector.v1.k8s.emberstack.com/reflection-auto-namespaces`: Namespace globs targeted for automatic reflection.
     - `reflector.v1.k8s.emberstack.com/reflects`: Pull-based reflection pointer to source `<namespace>/<name>`.

3. **Reconciliation & Idempotent Reflection Pipeline (`ResourceMirror<TResource, TWatcher>`)**:
   - Enforces bidirectional consistency: **Push Mode** (Source resource declares target destinations) and **Pull Mode** (Mirror target declares pointer to source resource).
   - Computes state hashes to suppress unnecessary Kubernetes API mutations: avoids infinite write amplification loops where reflection triggers an `ADDED`/`MODIFIED` event back into the watcher.
   - Cleanses Kubernetes system metadata: removes `resourceVersion`, `uid`, `creationTimestamp`, `ownerReferences`, and `managedFields` before applying payload mutations to target namespaces.

## 2. Net-New Universal Engineering Rules (Candidates for Master Brain)

### 1. In-Memory Hash Divergence Verification for Operator Loops
**RULE**:
Before issuing a `Create`, `Update`, or `Patch` request to the Kubernetes API server for a downstream resource mirrored from an upstream source, the controller MUST compute a canonical cryptographic hash (e.g., SHA256) of the source data payload and store it in an annotation (`reflector.v1.k8s.emberstack.com/reflected-version` or hash). On receipt of an update or watch event, the controller MUST compare the incoming source hash against the target resource's existing hash annotation. If the hashes are identical, the controller MUST short-circuit reconciliation and drop the write operation.

**WHY**:
Without payload hashing, mirroring triggers an infinite write amplification cycle:
1. Source changes $\to$ Operator writes target mirror.
2. Target mirror write emits an API watch event (`MODIFIED`).
3. Operator handles `MODIFIED` event, checks rules, and writes again unless strict equality is validated.
Additionally, naive object comparison on full Kubernetes resource structs fails due to dynamic metadata mutation injected by the API server (e.g., `resourceVersion`, timestamps, `managedFields`). Hashing strictly the business payload (`Data`, `BinaryData`, `StringData`) isolates functional drift from control-plane noise.

**WHEN TO APPLY**:
Apply to all controllers, operators, and daemons synchronizing resources across namespaces, clusters, or storage backends where the write target is also an observed source in the watch stream.

**VERIFIED IMPLEMENTATION PATTERN**:
```csharp
using System.Security.Cryptography;
using System.Text;
using System.Text.Json;
using k8s.Models;

public static class ResourceIntegrityEngine
{
    private const string ReflectedHashAnnotation = "reflector.v1.k8s.emberstack.com/reflected-hash";

    public static string ComputePayloadHash(IDictionary<string, byte[]> binaryData, IDictionary<string, string> stringData)
    {
        using var sha256 = SHA256.Create();
        using var stream = new MemoryStream();
        using var writer = new BinaryWriter(stream, Encoding.UTF8, leaveOpen: true);

        // Sort keys lexicographically to guarantee deterministic hashing
        if (binaryData != null)
        {
            foreach (var kvp in binaryData.OrderBy(k => k.Key, StringComparer.Ordinal))
            {
                writer.Write(kvp.Key);
                writer.Write(kvp.Value.Length);
                writer.Write(kvp.Value);
            }
        }

        if (stringData != null)
        {
            foreach (var kvp in stringData.OrderBy(k => k.Key, StringComparer.Ordinal))
            {
                writer.Write(kvp.Key);
                var bytes = Encoding.UTF8.GetBytes(kvp.Value);
                writer.Write(bytes.Length);
                writer.Write(bytes);
            }
        }

        writer.Flush();
        stream.Position = 0;
        return Convert.ToHexString(sha256.ComputeHash(stream));
    }

    public static bool NeedsReconciliation(V1Secret source, V1Secret target)
    {
        var sourceHash = ComputePayloadHash(source.Data, null);
        
        if (target.Metadata?.Annotations != null &&
            target.Metadata.Annotations.TryGetValue(ReflectedHashAnnotation, out var targetHash))
        {
            if (string.Equals(sourceHash, targetHash, StringComparison.OrdinalIgnoreCase))
            {
                return false; // Payload is identical. Suppress API mutation.
            }
        }

        return true; // Target missing hash or hash mismatch. Reconciliation mandatory.
    }
}
```

### 2. Resilient Kubernetes Watch Stream Auto-Reconstruction Invariant
**RULE**:
A Kubernetes resource watcher MUST NOT rely solely on the stream remaining open indefinitely, and MUST NOT terminate the background service when the watch stream closes or throws an EOF/Timeout. A watcher MUST configure an active, non-blocking reconnect loop utilizing Polly resilience pipelines with exponential backoff and jitter. It MUST track the latest valid `resourceVersion`, pass that `resourceVersion` on reconnect, and fall back to a full `LIST` synchronization if an `HTTP 410 Gone` (Expired ResourceVersion) error is received.

**WHY**:
Kubernetes API servers periodically terminate long-lived watch connections (typically every 30–60 minutes via `etcd` compaction or API server proxy timeouts like Envoy/Kube-Router). If the watcher does not catch closure gracefully or fails to restart the stream, the operator silently enters a "zombie" state where the process is running, health checks pass, but no updates are processed. Failing to track `resourceVersion` results in missed mutations during the disconnect window.

**WHEN TO APPLY**:
Apply to all Kubernetes controllers, background workers, and daemons using raw client watch mechanisms (`k8s.Watcher<T>` or HTTP chunked streaming) instead of high-level cached informers.

**VERIFIED IMPLEMENTATION PATTERN**:
```csharp
using System.Net;
using k8s;
using k8s.Autorest;
using Polly;
using Polly.Retry;

public abstract class ResilientWatcher<TResource, TList> : BackgroundService 
    where TResource : IKubernetesObject<V1ObjectMeta>
{
    private readonly IKubernetes _client;
    private readonly ILogger _logger;
    private string _lastResourceVersion = string.Empty;

    protected ResilientWatcher(IKubernetes client, ILogger logger)
    {
        _client = client;
        _logger = logger;
    }

    protected abstract Task<HttpOperationResponse<TList>> ListResourcesWithHttpMessagesAsync(
        string resourceVersion, CancellationToken ct);

    protected abstract Task<HttpOperationResponse<TResource>> CreateWatchStreamWithHttpMessagesAsync(
        string resourceVersion, CancellationToken ct);

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        var resiliencePipeline = new ResiliencePipelineBuilder()
            .AddRetry(new RetryStrategyOptions
            {
                ShouldHandle = new PredicateBuilder().Handle<Exception>(ex => !(ex is OperationCanceledException)),
                MaxRetryAttempts = int.MaxValue,
                Delay = TimeSpan.FromSeconds(2),
                BackoffType = DelayBackoffType.Exponential,
                UseJitter = true,
                OnRetry = args =>
                {
                    _logger.LogWarning(args.Outcome.Exception, "Watcher stream failed. Retrying reconnect attempt {Attempt}.", args.AttemptNumber);
                    return ValueTask.CompletedTask;
                }
            })
            .Build();

        while (!stoppingToken.IsCancellationRequested)
        {
            await resiliencePipeline.ExecuteAsync(async stateToken =>
            {
                try
                {
                    await RunWatchLoopAsync(stateToken);
                }
                catch (HttpOperationException httpEx) when (httpEx.Response.StatusCode == HttpStatusCode.Gone)
                {
                    _logger.LogWarning("ResourceVersion '{Version}' expired (410 Gone). Resetting to List sync.", _lastResourceVersion);
                    _lastResourceVersion = string.Empty; // Force full LIST sync
                    throw; // Re-throw to let Polly handle backoff before resyncing
                }
            }, stoppingToken);
        }
    }

    private async Task RunWatchLoopAsync(CancellationToken ct)
    {
        if (string.IsNullOrEmpty(_lastResourceVersion))
        {
            using var listResponse = await ListResourcesWithHttpMessagesAsync(string.Empty, ct);
            var metadata = (listResponse.Body as IKubernetesObjectList<TResource>)?.Metadata;
            _lastResourceVersion = metadata?.ResourceVersion ?? string.Empty;
        }

        using var watchResponse = await CreateWatchStreamWithHttpMessagesAsync(_lastResourceVersion, ct);
        using var watcher = watchResponse.Watch<TResource, TList>(
            onEvent: (type, item) =>
            {
                _lastResourceVersion = item.Metadata.ResourceVersion;
                OnResourceEvent(type, item);
            },
            onError: ex =>
            {
                _logger.LogError(ex, "Exception in watch stream connection.");
            },
            onClosed: () =>
            {
                _logger.LogInformation("Watch connection closed by upstream. Triggering reconnect.");
            });

        // Wait indefinitely until cancellation or stream closure
        var tcs = new TaskCompletionSource();
        using (ct.Register(() => tcs.TrySetCanceled()))
        {
            await tcs.Task;
        }
    }

    protected abstract void OnResourceEvent(WatchEventType type, TResource item);
}
```

**NEGATIVE CONSTRAINT**:

## 3. Forensic Real Incidents & Production Patches

### Incident 1: Silent Watch Stream Deserialization & Session Drop (BUG-REFLECTOR-01)
- **Context**: `src/ES.Kubernetes.Reflector/Watchers/Core/WatcherBackgroundService.cs` & `SecretWatcher.cs`
- **What Was Expected**: `SecretWatcher` and `ConfigMapWatcher` must run continuously throughout the container lifecycle. When a session terminates (either via API server timeout or socket reset), the session must immediately resurrect itself, re-list or re-watch, and maintain continuous active reflection of dynamic secrets (e.g., Let's Encrypt certificates generated by `cert-manager`).
- **What Actually Happened**: (Issue #341) In production clusters (such as AKS 1.25), `SecretWatcher` logged `Session closed. Duration: 00:41:46. Faulted: False.` and re-requested resources. However, after several cycles, the background watcher stopped receiving events completely while the container remained running and green in kubelet liveness probes. Secrets ceased reflecting, causing production SSL/TLS certificates to expire.
- **Evidence in Repo**: GitHub Issue #341: *"Reflector not watching secrets after period of time"*; Log: `(ES.Kubernetes.Reflector.Core.SecretWatcher) Session closed. Duration: 00:41:46.4948709. Faulted: False.`
- **Root Cause**: The underlying `Watcher<T>` from `k8s` client relies on an active HTTP/1.1 chunked stream. When the upstream gateway (e.g., AKS Azure Load Balancer or Envoy) times out an idle connection silently without sending a TCP `FIN` packet, the socket enters a half-open state. The `Watcher<T>` internal reader thread blocked on reading the line, while `onClosed` was never invoked. Furthermore, when exceptions were caught, the execution thread exited the `while` loop due to uncaught cancellation/transport exceptions bypassing the reconnection cycle.
- **Remediation Code Diff**:
```csharp
// - Buggy code / What failed: Unbounded read without watcher timeout config
- var response = await client.CoreV1.ListSecretForAllNamespacesWithHttpMessagesAsync(
-     watch: true, 
-     cancellationToken: cancellationToken);
- watcher = response.Watch<V1Secret, V1SecretList>(OnEvent, OnError, OnClosed);

// + Fixed pattern / Safe invariant: Injection of watcher timeout & Polly circuit breaker/retry
+ var timeoutSeconds = _options.Watcher.Timeout > 0 ? _options.Watcher.Timeout : 300;
+ var response = await client.CoreV1.ListSecretForAllNamespacesWithHttpMessagesAsync(
+     watch: true,
+     timeoutSeconds: timeoutSeconds,
+     cancellationToken: cancellationToken);
+ watcher = response.Watch<V1Secret, V1SecretList>(
+     onEvent: (type, item) => OnEventInternal(type, item),
+     onError: ex => HandleWatchException(ex),
+     onClosed: () => HandleWatchClosed());
```
- **Lesson**: Long-lived Kubernetes watch requests must enforce explicit server-side `timeoutSeconds` parameters. Setting an explicit timeout forces the API server to cleanly terminate the chunked response at deterministic intervals, preventing silent TCP deadlocks in cloud load balancers.

## 4. Microscopic Code-Level Invariants (Syntax, Infinite Loop, UI/UX & Concurrency Guards)

### 1. Micro-Syntax & Token-Level Precision
In C# Kubernetes controllers, metadata dictionaries and byte arrays exhibit unique nullability and serialization behaviors:
- **Null vs. Empty Dictionary Pitfall**: `V1Secret.Data` is an `IDictionary<string, byte[]>`, but can be `null` if a secret contains only `StringData` before admission mutation. Accessing `secret.Data["tls.crt"]` without null coalescence throws `NullReferenceException`.
  ```csharp
  // DEFECTIVE:
  var cert = secret.Data["tls.key"]; // Throws if Data is null or key absent

  // IMMUTABLE SAFE GUARD:
  if (secret.Data?.TryGetValue("tls.key", out var certBytes) == true && certBytes.Length > 0)
  {
      // Safe execution
  }
  ```
- **StringData Write-Only Masking**: `V1Secret.StringData` is write-only in the Kubernetes API. The API server encodes entries from `StringData` into `Data` (base64) and strips `StringData` on read responses. An operator comparing `source.StringData` with `target.StringData` will compare non-null against `null`, causing an erroneous update loop. Operators MUST only assert equivalence against `Data`.

### 2. Infinite Loop & Recursion Guards
Cross-namespace mirroring creates potential infinite reflection loops if namespace targets match wildcard or mutual reflection rules (e.g., Namespace A reflects to B, and Namespace B reflects to A):
- **Base Termination Proof**: Every reflected resource MUST be branded with a system annotation denoting its parent lineage: `reflector.v1.k8s.emberstack.com/reflected-from: <source-namespace>/<source-name>`.
- **Termination Invariant**:
  ```csharp
  public static bool IsMirror(V1ObjectMeta metadata)
  {
      if (metadata.Annotations == null) return false;
      return metadata.Annotations.ContainsKey("reflector.v1.k8s.emberstack.com/reflected-from");
  }

  // TERMINATION INVARIANT CHECK:
  if (IsMirror(sourceResource.Metadata))
  {
      // HALT: A mirrored resource can NEVER become a source for downstream reflection.
      return; 
  }
  ```
- **Glob Matcher Self-Reference Exclusion**: When expanding target namespaces with patterns such as `*`, the source resource's own namespace MUST be explicitly pruned prior to invoking reconciliation:
  ```csharp
  var targetNamespaces = allNamespaces
      .Where(ns => globMatcher.IsMatch(ns))
      .Where(ns => !string.Equals(ns, sourceResource.Metadata.NamespaceProperty, StringComparison.Ordinal))
      .ToList();
  ```

### 3. UI & UX Micro-Mechanics
*(Applied to the Helm Chart deployment lifecycle and CLI feedback)*
- **Kubectl Rolling Upgrade Desync**: When updating Helm values, annotations on secrets can trigger rolling Pod restarts before secrets are reflected across all target namespaces.
- **Micro-Mechanic**: The Helm deployment manifest (`src/helm/reflector/templates/deployment.yaml`) must enforce `strategy.type: RollingUpdate` with `maxSurge: 1` and `maxUnavailable: 0`. This guarantees the incoming controller replica is up, healthy, and watching before the legacy replica terminates, preventing synchronization blind spots.

### 4. Backend Concurrency & Memory Safety
- **TOCTOU Race Condition (Create vs. Update Conflict)**:
  Between the moment Reflector lists namespaces and issues a `CreateNamespacedSecretAsync`, another process (or a concurrent watch event) may have created the resource, resulting in `HTTP 409 Conflict`.
  ```csharp
  // CONCURRENCY GUARD:
  try
  {
      await _client.CoreV1.CreateNamespacedSecretAsync(targetSecret, targetNamespace);
  }
  catch (HttpOperationException ex) when (ex.Response.StatusCode == HttpStatusCode.Conflict)
  {
      // Resource created concurrently. Re-fetch and replace instead.
      var existing = await _client.CoreV1.ReadNamespacedSecretAsync(targetSecret.Metadata.Name, targetNamespace);
      targetSecret.Metadata.ResourceVersion = existing.Metadata.ResourceVersion;
      await _client.CoreV1.ReplaceNamespacedSecretAsync(targetSecret, targetSecret.Metadata.Name, targetNamespace);
  }
  ```
- **Unbounded Channel Microtask Memory Leaks**:
  Event handlers reading from Kubernetes watch streams must not use unbounded queues (`Channel.CreateUnbounded<T>()`). A rapid cluster re-indexing or secret mutation storm will trigger out-of-memory crashes (`OOMKilled`). Use bounded channels with `BoundedChannelOptions` and `FullMode.Wait`.

### 5. Defect & Error Prevention ("Galti Pakadna")
- **Off-By-One Boundary in Glob Matchers**:
  When evaluating namespaces against glob patterns (e.g., `prod-*`), regex conversion must enforce anchoring tokens `^` and `$`.
  ```csharp
  // DEFECTIVE REGEX TRANSLATION:
  var regex = new Regex(globPattern.Replace("*", ".*")); // Matches "my-prod-app" against "prod-*"!

  // SAFE ANCHORED REGEX:
  var regex = new Regex("^" + Regex.Escape(globPattern).Replace(@"\*", ".*") + "$", RegexOptions.Compiled | RegexOptions.IgnoreCase);
  ```
- **Metadata Scrubbing Defect**:
  Attempting to push an existing source secret object directly into `CreateNamespacedSecretAsync` without clearing its metadata causes immediate rejection by the Kubernetes admission controller.
  ```csharp
  public static V1ObjectMeta CloneSanitizedMetadata(V1ObjectMeta source, string targetNamespace)
  {
      return new V1ObjectMeta
      {
          Name = source.Name,
          NamespaceProperty = targetNamespace,
          Labels = source.Labels != null ? new Dictionary<string, string>(source.Labels) : new(),
          Annotations = source.Annotations != null ? new Dictionary<string, string>(source.Annotations) : new()
          // Explicitly OMIT: ResourceVersion, Uid, CreationTimestamp, Generation, ManagedFields, OwnerReferences
      };
  }
  ```

## 5. The 9 Deep Learning Dimensions

### Dimension 1: Architecture
The architecture is structured around the **Reactive Controller Loop** model within the .NET Generic Host ecosystem (`Microsoft.Extensions.Hosting`).
- **Subsystem Decoupling**: Separation between Watchers (`WatcherBackgroundService<TResource>`) and Action Handlers (`ResourceMirror<TResource>`). Watchers produce event stream records; mirrors consume them.
- **State Ownership**: Pure external state machine. Reflector maintains no local persistent database. The Kubernetes cluster state is the single source of truth. State synchronization is strictly deterministic and idempotent based on Kubernetes annotations.

### Dimension 2: Core Abstractions
- `ResourceMirror<TResource>`: Generic domain processor that enforces reflection rules.
- `MirroringProperties`: Immutable value record deserialized from annotation sets parsing `reflection-allowed`, `reflection-allowed-namespaces`, `reflects`, and `reflection-auto-enabled`.
- `WatcherEvent<TResource>`: Internal encapsulation of `(WatchEventType Type, TResource Item)`.
- `GlobMatcher`: Abstracted namespace pattern-matching utility implementing wildcard matching.

### Dimension 3: Error Handling
- **Polly v8 Pipelines**: Replaces ad-hoc try-catch blocks with standardized retry policies configured with exponential jitter backoff.
- **Fault Domain Isolation**: An exception when reflecting a secret to Namespace `alpha` does not prevent reflection to Namespace `beta`. Target namespace iterations execute within isolated exception protection boundaries.

### Dimension 4: Testing
- **Integration Harness**: Integration testing via `Testcontainers.K3s` allows real-world execution against actual embedded K3s clusters rather than mocked API mocks.
- **Fixtures (`ExcludedNamespacesReflectorFixture`)**: Deploys the operator in containerized test suites, injects test secrets with wildcards, and verifies the exact propagation timing and exclusion boundaries in true Kubernetes API semantics.

### Dimension 5: Security
- **Cross-Namespace Escalation Guard**: Reflector acts as a privileged proxy. If Namespace `dev` could annotate a secret with `reflector.v1.k8s.emberstack.com/reflects: "kube-system/cluster-admin-token"`, it could steal root credentials. Reflector mitigates this via mandatory **mutual consent**:
  - The source resource MUST have `reflection-allowed: "true"`.
  - The source resource MUST authorize the destination in `reflection-allowed-namespaces`.
  - Without explicit push authorization from the source, pull requests (`reflects`) are strictly rejected.

### Dimension 6: Performance
- **Zero-Copy Payload Reflection**: Where possible, raw byte buffers from `V1Secret.Data` are transferred without intermediate JSON string transformations.
- **Memory Footprint**: Designed to run with minimal resources (<64MB RAM, <50m CPU) in enterprise clusters with thousands of namespaces.

### Dimension 7: Deployment
- **Multi-Arch OCI Artifacts**: Standard cross-platform compilation targeting `linux/amd64`, `linux/arm64`, and `linux/arm`.
- **Helm Invariants**: Includes full support for Helm chart installation, PodDisruptionBudgets, HorizontalPodAutoscalers, and strict security contexts (`readOnlyRootFilesystem: true`, `runAsNonRoot: true`, `drop: [ALL]`).
