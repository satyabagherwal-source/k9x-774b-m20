## 2. Core Architectural Mechanisms
1. **Deterministic Tag Deduplication Algorithm**:
   - Every tag is assigned a deduplication key derived from its type and identifying attribute (e.g. `meta:name:description`, `meta:property:og:image`, `link:rel:canonical`).
   - If a child component declares a tag that matches an existing key, it cleanly replaces the previous value rather than creating duplicate tags in the DOM.
2. **Standardized Tag Sorting Pipeline**:
   - Automatically re-orders head elements according to W3C parser optimization:
     1. `<meta charset="utf-8">`
     2. `<meta name="viewport" ...>`
     3. `<title>`
     4. Base, Preconnect, Stylesheets, Meta, Scripts.
   - Guarantees charset stays within the first 1024 bytes and prevents premature head closure.
3. **SSR Hydration Reconciliation**:
   - Emits tags with unique hydration markers (`data-hid`) during server rendering. On client mount, Unhead reconciles against existing DOM nodes without destroying and rebuilding them.

## 3. Production Failure Modes & Anti-Patterns Defended
- **Failure Mode 1**: Multiple canonical tags or conflicting meta descriptions generated by nested routes. Defended by deterministic deduplication keys.
- **Failure Mode 2**: DOM flapping and layout shifts caused by un-debounced client-side head updates. Defended by microtask queue scheduling.
