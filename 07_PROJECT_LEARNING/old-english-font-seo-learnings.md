## 2. Forensic Discoveries & Root Causes

1. **Sitemap Contradiction**:
   - `scripts/generate-sitemap.mjs` dumped 39 localized utility routes (`/es/about/`, etc.) into `public/sitemap.xml`.
   - `public/robots.txt` pointed to `sitemap.xml`.
   - Meanwhile, Astro templates correctly flagged those routes with `noindex={true}`.
   - The project's existing audit script only checked `dist/sitemap-0.xml` generated by `@astrojs/sitemap`, creating a false-positive pass while Googlebot consumed `public/sitemap.xml`.
2. **Anchor Fragment in Redirection**:
   - `/frames/` redirected to `/generator/#decoratorSection 301`.
   - Fragment identifiers in 301 headers violate RFC 3986 and are flagged by GSC.
3. **Query Parameter Duplication**:
   - Header search button navigated via `/?search=true#fontSearchInput`, creating duplicate crawl targets canonicalizing to `/`.
4. **Thin Category Pages**:
   - 9 category pages had only ~190 words of boilerplate catalog text, causing Google's quality algorithms to de-index them after crawling.
5. **Crawl Budget Exhaustion**:
   - 616 URLs were simultaneously submitted on a new domain without priority or changefreq metadata.

## 4. Deep-Dive on Intentional Noindex vs GSC Exclusion (Human Directive)

**User Observation**: *"Excluded by ‘noindex’ tag wale pages me pages sources me noindex / nofollow add kar rakha h"*

### Analysis & Resolution:
1. **Confirmation**: In `src/pages/[lang]/(about|privacy|terms|contact).astro`, `noindex={true}` was explicitly configured, causing `Layout.astro` lines 84-86 to render `<meta name="robots" content="noindex, nofollow" />`.
2. **Why it was configured**: English utility pages (`/about/`, `/privacy/`, `/terms/`) are indexable. However, the 13 localized versions consisted of brief auto-translated legal boilerplate. Indexing 39 thin legal pages in Spanish, German, Japanese, etc. triggers Google's sitewide "Low Quality / Thin Content" algorithmic penalty. Setting `noindex` on localized legal pages is the **CORRECT industry standard**.
3. **Why GSC flagged it as an issue**: The issue was NOT the presence of `noindex` in the page source. The issue was that `scripts/generate-sitemap.mjs` submitted these 36 URLs in `public/sitemap.xml` directly to Google, while the footer language picker linked to them with dofollow links. This sent contradictory signals:
   - Sitemap said: *"Googlebot, please index this page."*
   - Page Source said: *"Googlebot, do NOT index this page."*
4. **Durable Resolution**:
   - Retain `noindex` on localized utility pages in page source.
   - Purge them completely from all sitemaps (`dist/sitemap-0.xml`).
   - Add `rel="nofollow"` to all internal language switcher links pointing to utility pages.
   - Omit `<link rel="canonical">` on noindex pages to prevent conflicting signals.

   - This eliminates 404 crawl errors for automated crawler discovery while preserving canonical robots.txt compliance.

## 10. Milestone v3.0: 404 Autopsy, Vite Cache Invalidation & Controlled Publication (37 -> 47 Fonts)

1. **Vite In-Memory Directory Map Caching on Windows**:
   - *Failure Mode*: A long-running local development server (`npm run dev`) that boots before new folders are created under `public/` will return HTTP 404 for files inside those newly created folders, even when the files physically exist on disk.
   - *Root Cause*: Vite static asset middleware builds an in-memory index of `public/` directory trees at startup on Windows. Newly created subtrees do not automatically register in the running file watcher's static router.
   - *Non-Destructive Fix*: Touching `astro.config.mjs` triggers an instant reload of the Vite server configuration without killing the long-running terminal process, re-indexing `public/` and instantly resolving the 404s to HTTP 200 OK.
2. **Catalog Publication Gate Invariants**:
   - Previous prompts explicitly prohibited publishing during discovery phases ("Do not publish fonts in this batch"). The discrepancy between 227 canonical assets and "Showing 6 of 37" on the website was an intentional staging boundary, not a data loss bug.
   - Promoting candidates from research staging to production requires 5 concurrent synchronization steps:
     1. Local binary download and cryptographic SHA-256 hash pinning.
     2. Registration in authoritative ledger (`src/data/fonts-registry.json`).
     3. Publication entry in `src/data/fonts.json`.
     4. Complete 14-language i18n metadata (`FONT_SUBSTYLE_NAMES`, `FONT_TAGLINES`, `FONT_DESCRIPTIONS`).
     5. Self-hosted `@font-face` CSS declarations in `src/styles/global.css`.
3. **Dynamic Verification vs Hardcoded Invariants**:
   - Verification scripts must never hardcode asset counts (e.g. `catalog.length === 37`). Tests must dynamically validate that `catalog.length === registry.length`, assert that all local binaries and license files exist on disk, match cryptographic hashes, and verify 100% translation key coverage across all supported locales.
