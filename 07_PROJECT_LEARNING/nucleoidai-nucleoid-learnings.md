## 1. Executive Forensic Architecture & System Mechanics

### Exact Problem Solved
Nucleoid is a neuro-symbolic, declarative logic programming runtime and world-model engine implemented in Rust (edition 2024, Rust 1.85, zero unsafe code via `#![forbid(unsafe_code)]`). Traditional Large Language Models (LLMs) struggle with deterministic logical deductions, stateful transitive consistency, invariant tracking, and multi-step relational computation over time. Conversely, classical Knowledge Graphs are purely static topological stores lacking executable reactive evaluation. 

Nucleoid resolves this dichotomy by acting as an **executable dependency logic graph**. In this paradigm:
1. Program statements (assignments, object definitions, relational constraints) are registered as reactive nodes and equations within a runtime dependency graph.
2. State changes trigger fine-grained incremental re-evaluation along topological dependency paths rather than sequential imperative mutation.
3. Declarative class templates (`$Class.property is <expression>`) dynamically bind to all living instances, maintaining relational invariants across population sets (e.g., set intersections, bounding-box recalculations, stencil complement overlaps in Abstraction and Reasoning Corpus [ARC] puzzles) with zero manual control-flow plumbing.

### Architectural Boundaries & State Ownership
- **Parsing & AST Layer (`src/lang/ast/`)**: Operates on a pure lexer stream generated by `logos`. Employs a recursive-descent parser enforcing rigid depth boundaries (`MAX_NESTING`). Contains specialized branch engines: `suite` and `suite_body` handling Python-style indentation (`Indent`/`Dedent`) alongside C-style blocks (`{ ... }`), statement tails (`is` vs `:=` vs `=`), and speculative hypothesis branches (`suppose` blocks with cached token attempts).
- **Declaration vs Instance Separation (`src/state.rs`)**: Enforces a strict boundary between `DeclarationKey` (class-level templates like `$Person.mortal`, keyed as string templates) and `NodeKey` (instance-level evaluation instances like `person1.mortal`). Class templates remain pure templates registered on `ClassData.declarations`, preserving sequence order via monotonic sequence IDs.
- **Transactional State Engine (`src/state/mutation.rs`)**: Encapsulates all mutating operations (`assign`, `assign_property`, `remove_property`, `insert_object`, `remove_object`). Direct mutations on `State` are prohibited. Every state mutation writes a synchronous before-image to `Transaction` before memory is mutated, enabling zero-copy transaction rollbacks without generating cascading undo-log cycles.
- **Order-Preserving Storage Subsystem (`indexmap`)**: All object property bags, instance registries, and class tables use `IndexMap` and `IndexSet`. Reversals, property deletion rollbacks (`restore_removed_property`), and deterministic serialization depend on physical index stability via `IndexMap::move_index`.
- **Neuro-Symbolic ARC Integration Layer (`arc/src/`)**: Combines TypeScript-driven LLM synthesis with the compiled Rust runtime. Visual grids are decomposed into symbolic object stencils (`holes`, `points`, `tags`), declarative NUC rules are compiled into the runtime graph, and deterministic constraint propagation computes ground-truth matrix outputs.

## 2. Net-New Universal Engineering Rules (Candidates for Master Brain)

### 1. Invariant Key Space Partitioning Between Templates and Instances
**RULE**:
A declarative or reactive graph engine MUST NOT represent class-level rule templates and instance-level computed state within the same graph key type. Class rules MUST use an explicit declaration template key (e.g., `DeclarationKey`), and instance nodes MUST use an instance-qualified node key (e.g., `NodeKey`).

**WHY**:
Unifying template and instance identifiers into a generic string or poly-type key causes structural namespace collisions, invalidates topological dependency resolution, corrupts instance cloning, and risks class-level definitions being overwritten or erroneously pruned when an instance node is garbage collected or rolled back.

**WHEN TO APPLY**:
Apply to any reactive runtime, compiler, semantic knowledge graph, entity-component system (ECS), or constraint solver where class-wide rules generate concrete per-instance dependencies.

**VERIFIED IMPLEMENTATION PATTERN**:
```rust
// Verified pattern derived from src/state.rs
use std::fmt;

/// Strongly typed DeclarationKey: represents class-level templates ($Class.property)
#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct DeclarationKey(String);

impl DeclarationKey {
    #[must_use]
    pub fn property(class: &str, property: &str) -> Self {
        DeclarationKey(format!("${class}.{property}"))
    }

    #[must_use]
    pub fn conditional(condition: &str) -> Self {
        DeclarationKey(format!("if({condition})"))
    }

    #[must_use]
    pub fn as_str(&self) -> &str {
        &self.0
    }
}

/// Distinct NodeKey: represents concrete, live instance graph dependencies (obj_1.property)
#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct NodeKey {
    pub instance_id: String,
    pub property: String,
}

impl NodeKey {
    #[must_use]
    pub fn property(instance_id: impl Into<String>, property: impl Into<String>) -> Self {
        Self {
            instance_id: instance_id.into(),
            property: property.into(),
        }
    }
}

pub struct ClassData {
    pub name: String,
    // Templates stored separately from concrete graph evaluations
    pub declarations: indexmap::IndexMap<DeclarationKey, Declaration>,
}

#[derive(Debug, Clone)]
pub struct Declaration {
    pub key: DeclarationKey,
    pub statement: String,
    pub sequence: u64,
}
```

### 2. Physical Index Preservation on Transactional Deletion-Rollback
**RULE**:
When implementing transaction rollback for insertion-ordered dictionaries (e.g., `IndexMap`), recording only the `(Key, Value)` pair on property deletion is STRICTLY PROHIBITED. The undo logger MUST record the 3-tuple `(Key, Value, PhysicalIndex)`, and rollback MUST re-insert the entry and reposition it via `move_index` to prevent iteration drift.

**WHY**:
In declarative logic engines, the iteration order of properties directly dictates serialization layouts, AST desugaring sequences, hashing digests, and rule firing precedence. Standard insertion on rollback places the restored element at the end (`length - 1`). Over repeated write-abort cycles, this permanently reshuffles object layout, breaking deterministic execution and spec invariants.

**WHEN TO APPLY**:
In any transactional runtime, AST transformer, database engine, or VM holding ordered dictionary state where semantic iteration order must survive abort/rollback operations.

**VERIFIED IMPLEMENTATION PATTERN**:
```rust
// Verified pattern derived from src/state.rs and src/state/mutation.rs
use indexmap::IndexMap;

pub struct PropertyStore {
    properties: IndexMap<String, String>,
}

pub enum UndoAction {
    RestoreRemovedProperty {
        object_id: String,
        property: String,
        index: usize,
        value: String,
    },
}

impl PropertyStore {
    pub fn remove_property(
        &mut self,
        object_id: &str,
        property: &str,
        undo_log: &mut Vec<UndoAction>,
    ) -> Option<String> {
        // shift_remove_full returns (index, key, value)
        if let Some((index, key, value)) = self.properties.shift_remove_full(property) {
            undo_log.push(UndoAction::RestoreRemovedProperty {
                object_id: object_id.to_string(),
                property: key,
                index,
                value: value.clone(),
            });
            Some(value)
        } else {
            None
        }
    }

    pub fn restore_removed_property(
        &mut self,
        property: String,
        index: usize,
        before: String,
    ) {
        // Step 1: Reinsert element (placed at end by default)
        let (current_index, _) = self.properties.insert_full(property, before);
        // Step 2: Shift back to exact original physical slot
        let target_index = index.min(self.properties.len() - 1);
        self.properties.move_index(current_index, target_index);
    }
}
```

**NEGATIVE CONSTRAINT**:
```rust
// ANTI-PATTERN: Restoring removed property via standard insert

    // BUG: Inserts at tail! The object's field layout has mutated permanently,
    // corrupting deterministic hashing and index-sensitive iteration.
    properties.insert(key, val); 
}
```

**VERIFICATION METHOD**:
Execute an automated sequence-permutation unit test:
```rust
#[test]
fn test_index_preservation_on_rollback() {
    let mut store = PropertyStore { properties: IndexMap::new() };
    store.properties.insert("a".into(), "1".into());
    store.properties.insert("b".into(), "2".into());
    store.properties.insert("c".into(), "3".into());

    let mut undo_log = Vec::new();
    // Delete "b" at index 1
    store.remove_property("obj", "b", &mut undo_log);
    assert_eq!(store.properties.keys().collect::<Vec<_>>(), vec!["a", "c"]);

    // Rollback
    for action in undo_log.into_iter().rev() {
        if let UndoAction::RestoreRemovedProperty { property, index, value, .. } = action {
            store.restore_removed_property(property, index, value);
        }
    }

    // Must match exact pre-deletion insertion order
    assert_eq!(store.properties.keys().collect::<Vec<_>>(), vec!["a", "b", "c"]);
}
```

### 3. Cycle-Guarded Successor Linearization for Prototype Chains
**RULE**:
Inheritance and prototype lineage iterators MUST NOT rely on unbounded `while let Some(...)` pointer/reference chasing. Lineage resolution MUST be strictly bounded by the total registered class count (`.take(self.classes.len())`) or track visited sets to prevent infinite loops in the event of cyclical parent references.

**WHY**:
Dynamic class systems or multi-pass transpilers can encounter circular prototypes (e.g., via desugared metaclasses, user error, or corrupted state deserialization). An unbounded recursive or `successors` traversal will permanently hang the thread, starving the host event loop or CPU worker.

**WHEN TO APPLY**:
Inheritance hierarchy traversal, scope-chain lookups, recursive prototype resolution, and AST symbol-table resolution in any language runtime.

**VERIFIED IMPLEMENTATION PATTERN**:
```rust
// Verified pattern derived from src/state.rs
use indexmap::IndexMap;
use std::iter;

pub struct ClassData {
    pub name: String,
    pub parent: Option<String>,
}

pub struct State {
    classes: IndexMap<String, ClassData>,
}

impl State {
    pub fn class(&self, name: &str) -> Option<&ClassData> {
        self.classes.get(name)
    }

    /// Traversing lineage safely using bounded successors
    pub fn lineage<'s>(
        &'s self,
        initial: Option<&'s ClassData>,
    ) -> impl Iterator<Item = &'s ClassData> {
        iter::successors(initial, |data| {
            data.parent.as_deref().and_then(|parent| self.class(parent))
        })
        // HARD INVARIANT: The lineage can never contain more nodes than total existing classes.
        // If a cycle exists (A -> B -> A), .take(...) guarantees termination without allocation.
        .take(self.classes.len())
    }
}
```

**NEGATIVE CONSTRAINT**:
```rust
// ANTI-PATTERN: Unbounded prototype traversal
pub fn bad_lineage<'a>(state: &'a State, mut current: Option<&'a ClassData>) -> Vec<&'a ClassData> {
    let mut result = Vec::new();
    // BUG: If cyclic inheritance is injected, this hangs indefinitely
    while let Some(data) = current {
        result.push(data);
        current = data.parent.as_deref().and_then(|p| state.class(p));
    }
    result
}
```

**VERIFICATION METHOD**:

### Incident 3: Non-Determinism and Mutation Leak in Property Deletion
- **Context**: State property mutation and rollback (`src/state.rs` & `src/state/mutation.rs`).
- **What Was Expected**: Calling `remove_property` followed by transaction abort/rollback must return the object property map to its exact identical hash, layout, and iteration sequence.
- **What Actually Happened**: Using a simple `.insert(property, value)` during rollback caused the restored property to be appended to the end of the `IndexMap`, completely changing object keys' iteration order and breaking downstream spec tests that depend on parameter/field ordering.
- **Evidence in Repo**: `src/state.rs`, `restore_removed_property` using `IndexMap::move_index`.
- **Root Cause**: An `IndexMap` preserves insertion order. When a property at index `k` is removed (`shift_remove_full`) and later restored, standard `.insert()` assigns it index `N - 1`.
- **Remediation Code Diff**:
```rust
// - Fragile property restore:
// pub(crate) fn restore_removed_property(&mut self, object: &ObjectId, property: String, before: Value) {
//     if let Some(data) = self.objects.get_mut(object) {
//         data.properties.insert(property, before);
//     }
// }

// + Order-preserving property restore with move_index:
pub(crate) fn restore_removed_property(
    &mut self,
    object: &ObjectId,
    property: String,
    index: usize,
    before: Value,
) {
    if let Some(data) = self.objects.get_mut(object) {
        let (current, _) = data.properties.insert_full(property, before);
        data.properties
            .move_index(current, index.min(data.properties.len() - 1));
    }
}
```
- **Lesson**: In systems where serialization, code generation, or method reflection depends on deterministic order, state-rollback operations must include topological index restoration.

### Incident 4: Redundant Change Propagation Storms on Self-Assignment
- **Context**: State reactive notification pipeline (`src/state/mutation.rs`).
- **What Was Expected**: Assigning an existing variable or property to an identical value (`a.x = 5` when `a.x == 5`) must be a no-op regarding reactive graph re-evaluation.
- **What Actually Happened**: Unconditional assignment caused `append_history` to log duplicate values and pushed downstream graph re-evaluations across all dependents, causing $O(D)$ wasted traversals and event loop thrashing.
- **Evidence in Repo**: `src/state/mutation.rs`, lines 40–55:
  ```rust
  let before = self.state.variables.get(name).cloned();
  let changed = before
      .as_ref()
      .is_none_or(|before| !before.same_value(&value));
  self.transaction.record_variable(name, before);
  if changed {
      self.append_history(HistoryKey::Variable(name.to_string()), &value);
  }
  ```
- **Root Cause**: Naive state engines treat every variable assignment as a mutation without checking value equality (`same_value`), causing history bloat and reactive cascade pollution.
- **Remediation Code Diff**:
```rust
// In src/state/mutation.rs:
// Compute `changed` prior to emitting notifications or recording history
let before = self.state.property(object, property).cloned();
let changed = before
    .as_ref()
    .is_none_or(|before| !before.same_value(&value));
let added = before.is_none();

if added {
    self.transaction.record_property_added(object, property);
} else {
    self.transaction.record_property(object, property, before);
}
if changed {
    self.append_history(
        HistoryKey::Property(object.clone(), property.to_string()),
        &value,
    );
}
```
- **Lesson**: Reactive dependency graphs must place value-equality gates directly ahead of change propagation pipelines.

### Incident 5: Exit Code Truncation in CLI Orchestrator
- **Context**: ARC Node/Bun runtime harness (`arc/server.ts`).
- **What Was Expected**: When the ARC solver evaluates grid differences, any mismatch count should accurately exit with an informative, non-zero exit code.
- **What Actually Happened**: Process exit codes in POSIX/Linux are unsigned 8-bit integers (`0..255`). If an ARC puzzle difference totaled exactly 256 mismatched cells, `process.exitCode = 256` evaluated to `0` modulo 256 in the host OS, signaling false-positive CI/CD success!
- **Evidence in Repo**: `arc/server.ts`, lines 18–25:
  ```typescript
  main()
    .then((difference: number) => {
      // Exit statuses keep eight bits, so 256 differences would read as 0.
      process.exitCode = Math.min(difference, 255);
    })
  ```
- **Root Cause**: Operating system exit statuses are masked with `0xFF` (`exit_status & 0377`).
- **Remediation Code Diff**:
```typescript
// - Naive assignment:
// process.exitCode = difference;

// + Guarded clamped exit status:
process.exitCode = Math.min(difference, 255);
```
- **Lesson**: Never map domain counts directly to OS process exit codes without capping at 255; otherwise, multiples of 256 will masquerade as exit code 0 (`SUCCESS`).

## 4. Microscopic Code-Level Invariants

### 1. Micro-Syntax & Token-Level Precision
- **Deep Immutability vs Shallow Mutation**: In `src/state/mutation.rs`, `insert_object` explicitly inspects the delta between existing properties and new incoming properties. Simply overwriting the pointer or map destroys history tracking:
  ```rust
  let removed: Vec<String> = self.state.object(&id).map_or_else(Vec::new, |before| {
      before
          .properties
          .keys()
          .filter(|property| !data.properties.contains_key(*property))
          .cloned()
          .collect()
  });
  ```
  Every property removed from the incoming object generates a specific `remove_history` call, while every unchanged property is preserved in place.
- **Falsy Comparisons and Value Identity**: Nucleoid disallows JS-style loose equality (`==`). In `src/state/mutation.rs`, `before.same_value(&value)` is used instead of standard Rust `PartialEq`. This ensures structural equality over complex numbers, dates, references, and nested list structures without converting `0`, `""`, or `false` to falsy equivalents.
- **Comment Parsing vs Delimiter Ambiguity**: In `README.md` and lexer specifications, comments (`//`, `#`, `/* */`) strictly take precedence over regex literals. An unescaped `//` is never parsed as an empty regex; empty regexes must be explicitly written as `/(?:)/`.

### 2. Infinite Loop & Recursion Guards
- **Parser Depth Invariant**: In `src/lang/ast/parser/statement.rs`, every statement parse pass increments `self.depth`. An explicit guard stops stack overflow attacks:
  ```rust
  self.depth += 1;
  if self.depth > MAX_NESTING {
      self.depth -= 1;
      return Err(self.error("Statements are nested too deeply"));
  }
  let depth = self.depth;
  let result = self.within(false, |parser| { ... });
  debug_assert_eq!(self.depth, depth);
  self.depth -= 1;
  ```
  The parser asserts that stack unwinding matches stack growth via `debug_assert_eq!`.
- **Suppose Premise Memoization**: Parsing hypothetical clauses (`suppose`) requires speculative lookahead. In `src/lang/ast/parser/statement.rs`, speculative parsing is memoized using `(self.position, self.depth)` keys in `self.suppose_premises` to prevent exponential $O(2^n)$ backtracking loops.

### 3. UI & UX Micro-Mechanics
- **Key Event Ambiguity (Windows vs Unix)**: Documented in `README.md`, Ctrl-Enter and Enter exhibit terminal driver discrepancies. On Windows, pasted `LF` generates the identical crossterm key code as `Ctrl-Enter`. The CLI workspace specifically remaps Enter to newline insertion and reserves F5 for explicit submission, neutralizing bracketed-paste bugs on Windows consoles.
- **Terminal Display Cell Metrics**: The workspace utilizes `unicode-width = "0.2"` to calculate the exact monospace display columns of Unicode characters before rendering Ratatui blocks, preventing cursor misalignment during multi-byte Chinese, Japanese, or emoji text rendering.

### 4. Backend Concurrency & Memory Safety
- **Read-Only Protection Guard**: Enums and frozen objects are secured against runtime mutation via an explicit runtime guard:
  ```rust
  pub(crate) fn ensure_writable(&self, object: &ObjectId) -> Result<()> {
      if self.state.is_read_only(object) {
          return Err(Error::type_error("Enums are read-only"));
      }
      Ok(())
  }
  ```
  `write_property` must invoke `ensure_writable` *before* attempting transaction recording or property mutation.
- **Transactional Undo Idempotency**: State rollbacks put before-images back directly into `State` fields without invoking `Runtime` mutation wrappers (`src/state.rs` vs `src/state/mutation.rs`). This architectural split ensures the undo log never logs its own rollback operations, preventing fatal infinite recursion or corrupted transaction states.

### 5. Defect & Error Prevention ("Galti Pakadna")
- **Shape Change Invalidation**: When properties are added or removed, object topologies alter. In `src/state/mutation.rs`, `queue_entries_change(object)` triggers `queue_shape_change(&ShapeKey::Entries(object.clone()))`. Dependent loops and entries iterators (`for key, value of object`) are flagged for re-computation only upon actual key insertion/removal, never on raw property updates.

## 5. The 9 Deep Learning Dimensions

### 1. Architecture
- **Paradigm**: Hybrid neuro-symbolic logic engine with declarative reactive graph propagation.
- **Modularity**: Complete separation between the pure AST syntax layer (`src/lang/ast/`), execution runtime (`src/runtime/`), reactive graph dependencies (`src/graph/`), state storage (`src/state/`), and the neuro-symbolic domain solver (`arc/src/`).
- **State Ownership**: `State` holds raw memory stores (`variables`, `objects`, `classes`, `functions`). `Runtime` owns `State` and `Transaction`. Mutating state is strictly mediated through `src/state/mutation.rs`.
