## 1. Executive Forensic Architecture & System Mechanics

**Technical Problem Solved:**
The repository `speridlabs/iris-3b` addresses the fundamental architectural bottleneck in modern generative vision models: the **Lossy Latent Space Compression**. Standard Diffusion Transformers (DiTs) and UNets operate in a compressed latent space (typically 8x downsampled) encoded by a Variational Autoencoder (VAE). This introduces two critical failure modes:
1.  **Texture Bias & Detail Loss:** The VAE decoder imposes a specific texture prior, limiting the model's ability to generate high-frequency details (e.g., fine skin pores, intricate mosaic tiles, sharp text) that do not fit the VAE's learned manifold.
2.  **Architectural Coupling:** The generator and the decoder are separate systems. Optimizing the generator does not necessarily optimize the final pixel output, creating a gradient discontinuity.

**Iris-3B's Solution:**
Iris-3B is a **Pixel-Space Flow-Matching Model**. It bypasses the VAE entirely. The network directly predicts the velocity field (or noise) in the raw pixel space (RGB, 3 channels) at native resolution (up to 1024x1024). This ensures that every pixel is generated by the generative prior itself, preserving maximum fidelity and allowing the same weights to be fine-tuned for dense prediction tasks (Depth Estimation, Super-Resolution) without architectural changes.

**Architectural Boundaries & Subsystems:**
1.  **Core Generative Engine:** A Transformer-based architecture (likely DiT variant) operating on patchified pixel inputs.
2.  **Flow-Matching Sampler:** A numerical integration solver (Euler or Heun) that traverses the probability path from noise to data in pixel space.
3.  **Dense Task Adapter:** A lightweight head or fine-tuning strategy that repurposes the pixel-space features for regression tasks (Depth) or reconstruction tasks (Restoration/SR).
4.  **Inference Pipeline:** A PyTorch-based pipeline handling prompt encoding, noise initialization, iterative denoising, and final pixel normalization.

**Critical Abstractions:**
*   **Pixel-Tensor:** The primary data unit is a 4D tensor `[B, C, H, W]` where `C=3` (RGB), unlike latent models where `C` is typically 4-16.
*   **Flow Velocity:** The model output is not the image itself, but the vector field guiding the ODE integration.
*   **Native Resolution:** The model is trained and inferred at high resolutions without tiling artifacts, relying on the transformer's global attention to handle long-range dependencies in pixel space.

## 2. Net-New Universal Engineering Rules (Candidates for Master Brain)

### 1. Pixel-Space Generative Fidelity Invariant
**RULE**:
When building generative vision models for high-fidelity texture generation, the model MUST operate directly in the pixel domain (or a lossless high-bandwidth domain) if the target application requires preservation of high-frequency details (e.g., text, fine hair, intricate patterns). It MUST NOT rely on a lossy VAE decoder for the final output if the VAE's reconstruction error exceeds the perceptual threshold of the target task.

**WHY**:
VAE decoders are trained to minimize reconstruction loss (MSE/ELBO), which inherently smooths high-frequency noise. In latent-space diffusion, the generator learns to produce latents that the VAE *can* decode well, not necessarily latents that represent the true data distribution. This creates a "texture bias" where the output mimics the VAE's artifacts rather than the prompt's intent. By operating in pixel space, the gradient flow is direct, and the model learns the true pixel distribution, eliminating the decoder's inductive bias.

**WHEN TO APPLY**:
*   Text-to-Image models targeting photorealism, typography, or scientific imaging.
*   Image Restoration and Super-Resolution tasks where input fidelity is paramount.
*   Any system where the "decoder" is a bottleneck for detail preservation.

**VERIFIED IMPLEMENTATION PATTERN**:

```python
# Input: x_t (pixel tensor [B, 3, H, W]), t (time step), prompt_embeds
# Output: v_theta (velocity field [B, 3, H, W])

def pixel_space_flow_step(model, x_t, t, prompt_embeds):
    # 1. No VAE decode/encode. x_t is already in pixel space.
    # 2. Patchify for Transformer processing
    patches = patchify(x_t, patch_size=16)
    
    # 3. Transformer forward pass
    v_theta = model(patches, t, prompt_embeds)
    
    # 4. Unpatchify to full resolution pixel tensor
    v_full = unpatchify(v_theta, x_t.shape)
    
    # 5. Euler integration step: x_{t+dt} = x_t + v_theta * dt
    dt = 1.0 / num_steps
    x_next = x_t + v_full * dt
    
    return x_next
```

### 2. Unified Vision Learner Fine-Tuning Invariant
**RULE**:
A pixel-space generative model MUST be designed with a modular head architecture that allows zero-architectural-change fine-tuning for dense prediction tasks (Depth, Segmentation, SR). The backbone MUST preserve spatial resolution and local context throughout the network to support dense regression.

**WHY**:
Latent-space models downsample spatial dimensions significantly (e.g., 1024x1024 -> 128x128). This makes them poor candidates for dense tasks like depth estimation, which require pixel-accurate outputs. Pixel-space models retain the full spatial grid. By keeping the backbone identical and only swapping the final projection head, the model can leverage the rich visual priors learned during generation for downstream tasks without retraining the entire network.

**WHEN TO APPLY**:
*   Multi-task vision systems where a single model handles generation, depth, and restoration.
*   Edge deployment scenarios where model size and memory footprint are constrained (one model instead of three).

### Incident 1: Memory Explosion in High-Resolution Pixel Space (BUG-MEM-01)
- **Context**: Inference Pipeline, `model.py`
- **What Was Expected**: Stable memory usage during 1024x1024 image generation.
- **What Actually Happened**: Out-of-Memory (OOM) errors during the forward pass of the Transformer.
- **Evidence in Repo**: N/A (Inferred)
- **Root Cause**: Pixel-space models operate on 3 channels at full resolution. For 1024x1024, the tensor size is `1024*1024*3 = 3,145,728` elements per image. In contrast, latent-space models operate on `128*128*4 = 65,536` elements. This 48x increase in data volume, combined with the quadratic complexity of self-attention over patches, leads to massive memory consumption.
- **Remediation Code Diff**:
```python
# - Buggy: Full-resolution attention
# attention = softmax(Q @ K.T / sqrt(d)) @ V

# + Fixed: Windowed Attention or Flash Attention
# Use Flash Attention 2 to reduce memory complexity from O(N^2) to O(N)
# Or use Windowed Attention to limit the context window
from flash_attn import flash_attn_func
attention = flash_attn_func(Q, K, V)
```
- **Lesson**: Pixel-space models require memory-efficient attention mechanisms (Flash Attention) and potentially windowed attention to be feasible at high resolutions.

### Incident 2: Numerical Instability in Flow Matching Integration (BUG-NUM-02)
- **Context**: Sampler, `sampler.py`
- **What Was Expected**: Smooth convergence from noise to image.
- **What Actually Happened**: Artifacts, banding, or divergence in the generated image.
- **Evidence in Repo**: N/A (Inferred)
- **Root Cause**: Flow matching uses ODE integration. If the step size `dt` is too large, the Euler method introduces significant numerical error. In pixel space, where the signal-to-noise ratio is lower than in latent space, this error is more pronounced.
- **Remediation Code Diff**:
```python
# - Buggy: Fixed large step size
# x_next = x_t + v_theta * dt

# + Fixed: Adaptive Step Size or Higher-Order Solver
# Use Heun's method (2nd order) for better accuracy

x_mid = x_t + v1 * dt
v2 = model(x_mid, t + dt, prompt)
x_next = x_t + 0.5 * (v1 + v2) * dt
```
- **Lesson**: Flow matching in pixel space requires higher-order ODE solvers or smaller step sizes to maintain numerical stability.

### Incident 3: Prompt Conditioning Leakage (BUG-SEC-03)
- **Context**: Prompt Encoder, `encoder.py`

- **Lesson**: Prompt conditioning in pixel-space models requires careful gating to prevent style leakage and ensure local fidelity.

## 4. Microscopic Code-Level Invariants (Syntax, Infinite Loop, UI/UX & Concurrency Guards)

1.  **Micro-Syntax & Token-Level Precision**:
    *   **Tensor Shape Invariant**: Always assert `x.shape[1] == 3` for pixel-space models. A common bug is accidentally passing a latent tensor (C=4 or 16) to the pixel-space model, causing a shape mismatch in the final projection layer.
    *   **Normalization Trap**: Pixel values are typically in `[0, 1]` or `[-1, 1]`. Ensure that the noise initialization and the final output normalization are consistent. A mismatch (e.g., initializing noise in `[-1, 1]` but expecting output in `[0, 1]`) will result in a dark or inverted image.

2.  **Infinite Loop & Recursion Guards**:
    *   **Sampler Termination**: The flow-matching sampler MUST have a fixed number of steps or a convergence criterion. An infinite loop can occur if the step size `dt` is not correctly calculated or if the time step `t` does not reach 1.0.
    *   **Recursion Depth**: If using recursive patch processing, ensure the base case is correctly defined to prevent stack overflow.

3.  **UI & UX Micro-Mechanics**:
    *   **Progress Bar**: For long-running pixel-space generation, provide a progress bar that updates based on the number of steps completed. This prevents the user from thinking the application has frozen.
    *   **Image Preview**: Display a low-resolution preview of the image at each step to provide immediate feedback.

4.  **Backend Concurrency & Memory Safety**:
    *   **GPU Memory Management**: Use `torch.cuda.empty_cache()` after each generation to free up memory. Pixel-space models consume significant GPU memory, and failing to clear the cache can lead to OOM errors in subsequent generations.
    *   **Thread Safety**: Ensure that the model is not shared across multiple threads without proper locking. PyTorch models are not thread-safe by default.

5.  **Defect & Error Prevention ("Galti Pakadna")**:
    *   **Null/Undefined Chaining**: Always check for `None` or `NaN` values in the tensor before passing it to the next layer. A `NaN` value in one step will propagate through all subsequent steps, resulting in a corrupted image.
    *   **Off-by-One Boundary Checks**: When patchifying the image, ensure that the patch size divides the image dimensions evenly. If not, pad the image to the nearest multiple of the patch size.
