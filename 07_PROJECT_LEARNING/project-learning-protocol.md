# Project Learning Protocol

This folder captures learning produced by real project work before that learning is promoted into the Master Brain.

## Purpose

Project learning preserves what actually happened in a project:
- observations,
- failures,
- successful approaches,
- unexpected behavior,
- important decisions,
- and lessons that may be reusable.

Project learning is not automatically permanent Brain knowledge.

## Learning record

For a meaningful learning event, capture:

1. Project and feature/context.
2. What was expected.
3. What actually happened.
4. Evidence used to establish what happened.
5. Immediate explanation or hypotheses.
6. What was changed or tested.
7. What happened after the change.
8. Candidate lesson.
9. Scope: project-specific or potentially reusable.
10. Confidence and unresolved uncertainty.

## Promotion boundary

A project observation stays here when it is:
- only a fact about one project,
- insufficiently verified,
- dependent on a specific environment/version,
- or not clearly reusable.

A candidate can move toward Master Brain knowledge only after verification and review.

## First real test

The Website Change Monitor project is the first real-world source for testing this protocol.
