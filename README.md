### 3. The Daily Auto-Harvesting Persistence Rule
> **"Persistence is Mandatory; New Knowledge is Conditional."**  
> *"Har din harvesting chalna aur har din nayi knowledge milna do alag baatein hain. Har scheduled cycle ka execution, checkpoint aur outcome record hona chahiye, lekin `05_KNOWLEDGE` me kewal vastavik, verified reusable learning hi jaani chahiye."*

1. **Physical File Write Required**: Console logs, AI responses, temporary memory objects, or chat reports do NOT constitute stored learning. A learning exists ONLY when written to its destination `.md`/`.json` file, verified via SHA-256 read-back, and committed to Git.
2. **Mandatory Metadata per Learning**:
   - Stable Unique ID (`learn-<source>-<hash>`)
   - Traceable Source & Commit SHA
   - Empirical Evidence & Test Reproduction
   - Verification Status (`VERIFIED`, `PARTIALLY_VERIFIED`, `REJECTED`, `UNCERTAIN`)
   - Exact Timestamp (ISO 8601)
3. **Fault-Tolerant Pipelines**: Harvesters must incorporate duplicate detection, atomic file writes, retry mechanisms, and checkpoint recovery. A temporary network fetch failure must never corrupt existing verified knowledge.
4. **The Cardinal Philosophy**:  
   *"पहले सीखना, फिर सत्यापित करना, फिर स्थायी रूप से सहेजना — कमाई उसके बाद।"*  
   (First Learn, Then Verify, Then Permanently Persist — Earnings Follow).
